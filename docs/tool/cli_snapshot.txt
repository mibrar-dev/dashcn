$ dashcn --help
dashcn CLI
Usage: dashcn <command> [arguments]

Components
  add                     Install one or more components or blocks and their closure.
  eject                   Turn a package-mode component into owned sources.
  remove (alias: rm)      Remove installed components, blocks and orphaned layer files.
  update                  Update installed components from the registry.
  dry-run                 Preview what add would install.
  list (alias: ls)        List available components or blocks, by category.
  search                  Search components and blocks by name, description or tag.
  info (alias: i)         Show a component's or block's closure, files and api.

Project
  init                    Install the layer core and generate the app theme.
  registries              List configured and discoverable registries.
  default                 Set or show the default registry namespace.
  sync                    Re-apply the installed closure and locked theme.
  project                 Project repair and cleanup commands.
  theme                   List and apply registry theme presets.

Diagnostics
  reset                   Clear global CLI-managed cache and home-directory state.
  doctor                  Diagnose the manifest, closure, layout and lock drift.
  validate                Validate the registry manifest against the v2 schema.
  audit                   Compare installed files against dashcn.lock.

Tooling
  feedback                Submit feedback or report issues.
  version                 Show the CLI version.
  upgrade                 Upgrade the CLI to the latest version.

Global flags
  General:
    --verbose               Verbose logging
    --version               Show the CLI version
    --offline               Disable network calls (use cache only)

  Registry Selection:
    --registry-name         Registry namespace (e.g. dashcn)
    --registry <path|url>   Registry source override

$ dashcn init --help
Usage: dashcn init [flags]

Installs the always-on foundation + theme core and generates
<installRoot>/theme/app_theme.dart from a theme preset.

Options:
  --dir <path>     Install root (default: lib/ui/dashcn)
  --theme <id>     Theme preset id (default: neutral)
  --mode <mode>    `copy` (own the sources) or `package` (pub dep)
  --yes, -y        Non-interactive; use the default preset
  --json           Machine-readable output on stdout
  --help, -h       Show this message

$ dashcn add --help
Usage: dashcn add <component|block...> [flags]
       dashcn add --all [--blocks] [flags]

Installs the transitive closure of every requested id:
components, blocks, primitives, and the always-on foundation/theme core.
A block installs to blocks/<id>/ with the components it uses.

Options:
  --all               Install every component in the registry
  --blocks            With --all, install every block too
  --dry-run           Print the plan without writing anything
  --force             Overwrite locally modified registry files
  --include-preview   Also copy each component preview.dart
  --package           Depend on the dashcn package, copy no sources
  --path <dir>        With --package, use a path dependency instead
  --json              Machine-readable output on stdout
  --help, -h          Show this message

$ dashcn eject --help
Usage: dashcn eject <component> [flags]

Turns a mode: package component into owned sources in the
install dir and rewrites the app imports to match.

Options:
  --with-deps         Also eject transitive component dependencies
  --dry-run           Print the plan without writing anything
  --force             Overwrite locally modified registry files
  --json              Machine-readable output on stdout
  --help, -h          Show this message

$ dashcn remove --help
Usage: dashcn remove <component|block...> [flags]
       dashcn remove --all [flags]

Options:
  --all                 Remove every installed component and block
  --force               Remove even if dependents remain
  --purge-user-themes   Also delete <name>_theme.dart user files
  --json                Machine-readable output on stdout

$ dashcn update --help
Usage: dashcn update [component...] [flags]
       dashcn update --all [flags]

Updates installed components to the registry's current files.
Files you edited are reported and left untouched; user-owned
<name>_theme.dart files are never rewritten.

Options:
  --all     Update every installed component
  --check   Report only; exit 1 when anything is behind or modified
  --json    Machine-readable output on stdout

$ dashcn theme --help
Usage: dashcn theme list [--json]
       dashcn theme apply <preset> [--refresh] [--json]
       dashcn theme import <file|url> [--name <id>] [--apply]
       dashcn theme export [--format css|tailwind|dtcg|json|dart]
                           [--out <file>]
       dashcn theme

Commands:
  list              Show the presets from the registry manifest
  apply <preset>    Generate <installRoot>/theme/app_theme.dart
  import <file|url> Store a web theme as <installRoot>/theme/<id>.json
  export            Print the current theme in a web format

Options:
  --refresh         Overwrite app_theme.dart even when it was edited
  --json            Machine-readable output on stdout
  --name <id>       Preset id for an import (default: file name)
  --apply           Apply an import straight to app_theme.dart
  --format <name>   Export format: css|tailwind|dtcg|json|dart
  --out <file>      Write the export to a file instead of stdout
  --help, -h        Show this message

app_theme.dart is yours: without --refresh a locally modified file is
reported as drift and left untouched.

An import needs no registry: CSS, Tailwind v3 configs and preset JSON
parse into a stored preset; --apply renders it without one either.

Legacy flags --apply/-a and --list still work. --apply-file,
--apply-url and "theme widget" were removed with the v1 theme
manifest; use "theme import <file|url>" instead.
