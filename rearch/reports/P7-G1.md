# P7-G1 — Gooey Toast behaves like a real gooey toast (2026-10-11 user report)

Owner: P7-G1 agent. Reference behaviour: Sonner (duration 4000, hover-pause
with remaining-budget resume, swipe threshold, close button, promise/loading
toasts updated in place, `toast.dismiss(id)`, top-center position option) and
`anl331/goey-toast` (pill → expand, `displayDuration` 4000, hover pause +
re-expand, pre-dismiss collapse, close button top corners, Escape, 6 mirrored
positions, RTL/dark). Lifecycle implemented here: pill → morph open (150 ms
expand delay + 600 ms sileo) → expanded → collapse (4 s delay) → queue
`duration` (6 s default) → fade/slide exit (200 ms) → removed.

## Root causes fixed (bug → root → fix)

1. **Toast visible on page load.** `preview.dart` auto-fired a
   `persistUntilDismissed` toast in `initState`. Previews are now trigger
   buttons only (9 examples, each owning its controller); disposing the
   example disposes its controller, so leaving the page clears its toasts.
2. **Toast covered its own trigger inside the stage.** Each preview embedded
   the layer in a 360×220 box with the button at the top-left, the same
   corner the toast anchors to. Default `position` is now `center`
   (top-center edge, per brief); triggers sit at the stage bottom while
   toasts anchor to the top edge. README Setup now mandates one app-level
   `GooeyToastLayer` (viewport edge, never over the trigger). No Overlay
   rewrite: the layer already documents app-level wrapping, and an
   `OverlayPortal` port would re-anchor every existing position test and
   risk clipping/focus regressions — recorded, not done.
3. **Contrast.** The card painted the title in the state tone
   (`titleStyle.color ?? tone`) and the surface had no border/shadow.
   Title now reads `popoverForeground`; the tone tints the state icon (and
   action chip) only. New `GooeyToastTheme.borderColor` (default `border`
   token) + token `shadowLg` under the silhouette; fill stays `popover`.
   Tones keep the accepted chart/destructive/muted mappings.
4. **Always expanded, never dismisses.** Same root as (1) (persistent
   preview toasts). Real durations everywhere now; autopilot
   expand 150 ms / collapse 4 s / queue 6 s verified by test. Dismiss paths:
   `controller.dismiss/dismissSlot/dismissAll`, swipe (`GooeySwipe`), new
   `GooeyCloseButton` on the expanded body (tap, Enter/Space, Escape),
   focus pauses the countdown. Promise pattern = `loading` toast (never
   expands) + in-place `transition` update; documented in README and shown
   in the Loading preview.
5. **Two stacked rectangles.** `GooeyShapePainter` painted the body
   translucent (`alpha × bodyScaleY`) over the pill, leaving a visible seam.
   The silhouette is now one united path (`PathOperation.union` of pill +
   body + shoulders) painted opaque; the blur/threshold metaball pass fuses
   the morph, the crisp layer draws the same union plus 1 px token border
   and a token-coloured `drawShadow` (elevation 4; `drawShadow` cannot
   represent the token offset/spread atoms — documented approximation).
   Reduced motion (`MediaQuery.disableAnimations`) disables the blur pass,
   zeroes the open duration and snaps the body.
6. **Previews.** Default, Expanded, Success, Error, Warning, Info,
   With action, Positions (left/center/right), Loading — each a trigger
   button only.

## Latent bugs found while fixing (all fixed, with tests)

- **Card remounted the surface on expansion.** The card returned different
  tree shapes collapsed vs expanded, so `_GooeyToastCardState` expansion
  unmounted `GooeySurface`, resetting its animation (visible hitch in real
  time; broke fake-async timing in tests). The card now always returns the
  same `Stack`, with the close button conditional inside it.
- **Widget-identity change detection.** `didUpdateWidget` compared rebuilt
  `body`/`action` instances by identity, so every card rebuild rescheduled
  the autopilot (pushing collapse, re-expanding after collapse) and
  re-notified expansion, which `setState`d the card mid-build (framework
  exception). `GooeySurface.contentKey` (the card passes `options`, whose
  identity changes exactly on genuine updates) now drives rescheduling;
  `_syncOpen` notifies only on genuine transitions; the card defers its
  `setState` to a post-frame callback.

## Follow-up: edges + close button (user feedback, same day)

Screenshot `user-bugs-2026-10-11/gooey-toast-edges-close.png` (not viewed,
per brief): visible notches/steps and separately-stroked outlines at the
pill→body junction; close button floating outside the toast top-right.

1. **Single smooth silhouette.** `GooeyShapeGeometry` no longer unions
   rounded rects + shoulder ovals (a union is geometrically correct but not
   smooth — it keeps the width steps). `buildSilhouette` emits ONE closed
   contour: pill edges flare into the body through concave cubics with a
   vertical tangent on both ends; quadratic corners; continuous in
   `bodyScaleY` with no pop threshold (zero-height body == pill). Fill,
   shadow and the 1 px token border paint once around that contour.
   `buildPillPath`/`buildBodyPath`/`buildShoulderPath`/`buildUnitedPath`
   deleted (only tests + clipper/painter used them); clipper + painter use
   `buildSilhouette`.
2. **No blurred border fringe.** The gooey blur/threshold copy is now
   fill-only; border + shadow paint once in the crisp copy
   (`_GooeyShapeStack` takes `fill` + `crisp`). Previously the stroked
   border went through the blur pass too, leaving a visible fringe.
3. **Close button inside the body.** 24×24 hit target (18 px visual centred
   inside), positioned top-right inside the body with 8 px padding
   (`top: pillH + 8` growing down, `top: 8` growing up, `right: 8`). The
   card folds the description into its own body column with a 32 px right
   reserve mirroring `GooeySurfaceBody`'s default branch, so text never
   slides under the button; a custom `expandedChild` is used as-is and
   shares the corner (README-noted).
4. **Title** stays `popoverForeground`; tone on icon only (unchanged,
   re-locked by the contrast tests).

Tests: silhouette is a single contour closed/open/mid-morph
(`computeMetrics().length == 1`, exact open bounds, flare bounds);
close rect inside body rect with ≥ 8 px padding + hit target ≥ 24 px.
Found while testing: tickers need a warm-up frame — a single long
`pump(d)` never advances a just-started controller (first tick only stamps
start time), so lifecycle tests use split pumps; previously-mysterious
height-40 failures were harness artifacts, not product bugs.
