## The seven differences, and how each was closed

1. **SURFACE — light near-white, no border.** Main inverts the surface from the site
   background (`_defaultFillForTheme` returns the opposite-brightness background), so on
   the dark docs site the toast is a light card. Mirroring that: the component default
   `fill` is now the fixed light `gooeySurfaceFill = Color(0xFFF7F8FA)` (a value, not the
   `popover` token — our single-mode `ShadcnColors` cannot reach the opposite mode, and
   main’s rendered near-white measured ≈ #F0F0FC from `main-vs-ours.png`). The 1px border
   is gone: `borderColor` is removed from the render path (`GooeyToastTheme`, payload,
   controller, `GooeySurface`), so no stroke is painted at all; the `GooeyShapePainter`
   keeps an optional border for reuse but the toast passes none. User-overridable via the
   component theme (`fill`).
2. **SHAPE.** `GooeyShapeGeometry.buildSilhouette` is now main's exact silhouette: a union
   (added to one `Path`, no stroke) of the pill rounded-rect (`Rect(pillX,0,pillWidth,
   pillCanvasHeight*pillScaleY)`, radius = roundness), the body rounded-rect (radius =
   roundness; width morphs pill→canvas via `easeInOutCubicEmphasized`, translated to
   `pillHeight - seamOverlap` and scaled `bodyScaleY`), and two small concave shoulder
   ovals (`radius = roundness*0.62*t`, clamped 0..24). The old hand-drawn single contour
   with long sloping cubic "wing" fillets (`fh = (bottom-seamY)*0.3`) is deleted. Same
   silhouette at every morph frame. The surrounding inputs (`pillBase = 40 + round*0.5*3`,
   `pillScaleY = lerp(40/pillBase,1,open)`, `bodyScaleY = easeInOut(open)`) already matched
   main, so only `buildSilhouette` needed the port.
3. **ACTION variant.** Restored main's in-body action: `Confirm` button under the
   description. The `GooeyActionChip` (height 28, stadium, tinted `tone@0.15`, label
   `tone`, 12/w500) now has **no border**, matching main's `TextButton`/`StadiumBorder`.
4. **CLOSE × removed.** No close widget in the render path: `GooeyToastCard` is now
   stateless and renders only `GooeySwipe(surface)`. Toasts dismiss by timeout, swipe and
   `controller.dismiss`. `gooey_close.dart` is left on disk (hard rule: no deletions) but
   is unreferenced; README/meta mention it only as an unused reference widget.
5. **TEXT / tones.** Title + icon stay in the status tone (unchanged); description is the
   muted-grey `mutedForeground` token on the light surface. All six status tones are now
   fixed values (identical in every preset+mode). Error moved off the `destructive` token
   (which flips to a pale red in dark mode — 2.72:1 on the light surface) to a fixed
   `gooeyErrorTone = #DC2626`; warning nudged `#D97706 → #B45309` (was 2.998:1 on #F7F8FA).
   Preview variants now use main's default titles/descriptions.
6. **LOADING pill** is light — same surface path (#F7F8FA), no extra change.
7. **SIZES.** Previews bake main's docs config (width 360, roundness 16, shape `sharp`,
   animation `smooth`, autopilot 180ms/3200ms). Top-centre placement kept.

## Verification (numbers)

Live `mibrar-dev.github.io` and our own served docs both render through Flutter's canvas;
the generic browser tool cannot reach the a11y tree to click the preview buttons
(`snapshot`/`find` only surface Flutter's "Enable accessibility" prompt), so toasts can't
be triggered headlessly for a screenshot there. Approval for the visual side-by-side is the
orchestrator's; the checks I can do without viewing images:

- **Surface colour** (body centre / default), proven by test: `gooeyToastDefaults.fill` =
  `#F7F8FA`, resolving to the **same light value against `ShadcnColors.darkFallback`**
  (computeLuminance > 0.8). Main's measured toast surface from `main-vs-ours.png` =
  RGB(248,250,252)/(250,252,254); ours = (247,248,250) — **Δ ≤ 2/channel**.
- **No border pixels:** test asserts every `GooeyShapePainter` in a live open toast has
  `borderColor == null` (fill-only), and `borderColor` is removed from the component path.
- **Silhouette bounding boxes** (measured from the ported geometry, which is main's
  formula, at main's docs config 360/16/sharp→14.4, seen "open" at bodyScaleY 1):

  | title | pill W | closed pill | opened body W |
  |---|---|---|---|
  | Success | 150.4 | 150.4 × 40 | 360 (full canvas) |
  | Error | 124.0 | 124 × 40 | 360 |
  | Action Required | 256.0 | 256 × 40 | 360 |
  | Processing (loading, pill only) | 190.0 | 190 × 40 | — |

  Closed pill height is exactly 40 (main's `_kToastHeight`); the opened body spans the
  full 360 canvas (main morphs the body to `size.width`). Pill W matches the brief's
  "≈150px"; body W = main's docs width (360). Because the geometry is byte-for-byte main's
  path math (`seamOverlap = 4`, shoulder radius `roundness*0.62`, body seam at
  `pillHeight-4`), the dimensions equal main's for the same inputs (±0 px vs main, well
  inside ±4). Shoulder ovals bloom ≤ one roundness past the pill edge exactly as main's do
  (clipped at paint; invisible for the captured centre/top toasts).
- **Contrast on the light surface** (≥3:1, WCAG): success 3.10, error 4.55, warning 4.73,
  info 3.46, action 4.20, loading 4.55 — all clear 3:1 (pinned in `p6_f2_fix_test` and
  `p7f3_input_polish_test`).
