| property | main (code / measured) |
|---|---|
| surface fill | `#F8FAFC` = RGB(248,250,252), solid, same in every stage |
| border/stroke | **none** (edge sample x+1 == x+3 == 248 → uniform fill; code paints fill only) |

| pill width math | `24+8 + text + 16 + pillPadding(10)`, clamp(40, width) — identical to our `GooeySurfacePill.measureWidth` |

`_defaultFillForTheme` inverts the page background (dark site → light toast), so
main's docs toast is the light surface even in dark mode; `#F8FAFC` is the light
`card/popover` shade it lands on.

## The seven differences, and how each is closed

1. **SURFACE — light near-white, no border (both site modes).** The component
   default `fill` is the fixed light `gooeySurfaceFill = Color(0xFFF7F8FA)`
   (a value, not the `popover` token — our single-mode `ShadcnColors` cannot
   reach the opposite mode the way main's `_defaultFillForTheme` does). Main
   measures `#F8FAFC`; ours `#F7F8FA` is **Δ ≤ 2/channel** (imperceptible, inside
   the brief's ±2), and is user-overridable through the component theme (`fill`).
   No stroke: `borderColor` is not part of the toast render path
   (`GooeyToastTheme`, payload, controller, `GooeySurface`); `GooeyShapePainter`
   keeps an optional border for reuse but the toast passes none. Pinned by test.
2. **SHAPE.** `GooeyShapeGeometry.buildSilhouette` is main's exact silhouette:
   the union (one `Path`, no stroke) of the pill rounded-rect, the body
   rounded-rect (width morphs pill→canvas via `easeInOutCubicEmphasized`,
   translated to `pillHeight − seamOverlap`, scaled `bodyScaleY`), and two small
   concave shoulder ovals (`radius = roundness×0.62×t`, clamped 0..24). The old
   hand-drawn single contour with long sloping cubic "wing" fillets is gone.
   Same silhouette at every morph frame; identical math to main.
3. **ACTION variant.** Restored main's in-body `Confirm` button under the
   description: `GooeyActionChip` (height 28, stadium, tinted `tone@0.15`, label
   `tone`, 12/w500) with **no border**, matching main's
   `TextButton`/`StadiumBorder`. `ShadcnButton(isLoading: …)` was not used — it
   is pill-shaped; a `Container` reproduces main's stadium exactly.
4. **CLOSE × — gone.** No close widget anywhere in the render path; toasts
   dismiss by timeout, swipe or `controller.dismiss`. `GooeyCloseButton` stays
   defined (hard rule: no deletions) but the toast never instantiates it.
5. **TEXT / tones.** Title + icon stay in the status tone; description is the
   muted-grey `mutedForeground` token on the light surface. The six status tones
   are fixed values. `toastConfig(title:)` overrides in the previews were
   replaced by real `title:`/`description:` args (a preview bug: `toastConfig`'s
   `title` never reached the controller, so every preview pill read its hardcoded
   placeholder — "still not looking the same").
6. **LOADING pill** is light — the same `#F7F8FA` surface path, no extra change.
7. **SIZES — matched to main's docs config this pass.** The previews now bake
   **width 350, roundness 18, shape `defaultShape` (→ resolved 24.3)**, the
   default autopilot, top-centre placement. (They previously defaulted to
   `sharp`/16/360 — sharper corners and a 10px narrower body — which was the
   residual "still not the same"; main's docs passes no width/roundness and
   defaults to `defaultShape`.)

## Residual fix applied this pass (why it still looked different)

Commit `6f8262fc` (P7 polish batch) had already landed the port with the correct
geometry math, surface, action, no-close and tone-title behaviour — but its
preview defaulted to `GooeyToastShapeStyle.sharp` with `roundness = 16` and
`width = 360`, and the P7-G3 report asserted that was "main's docs config".
PIL-measuring main's own 1440 sequence shows main renders the **`defaultShape`**
silhouette at **width 350 / roundness 18 (resolved 24.3)**, i.e. visibly rounder
corners (a compact pill at radius 20, an expanded body at 24.3) on a slightly
narrower body than ours. Two one-line edits close it:

- `preview.dart`: `_Shared.shape` `sharp → defaultShape`; `_kWidth 360 → 350`;
  `_kRoundness 16 → 18`; added a `default` shape chip so the control reflects
  the initial state.
- `gooey_toast_p7g3_geometry_test.dart`: reference config re-pinned to
  `350 / 18 / defaultShape (24.3)` (was `360 / 16 / sharp (14.4)`).

With these, our rendered config == main's docs config, so the silhouette, widths
and roundness match main's for the same title/font (±0 px against main's path
formula). The tone **hues** remain the contrast-lifted fixed values (main's
`#63C65E` green is 2.57:1 on `#F8FAFC`, below the P7-F3 3:1 floor); that is a
deliberate, tested deviation the visual side-by-side already accepts.

## Verification (numbers)

- **Surface colour** (body centre, default), proven by the p7g3 test, which
  renders our real `GooeySurface`/`GooeyToastCard` and confirms the surface layer
  paints fill-only at the fixed light `gooeyToastDefaults.fill = #F7F8FA`,
  resolving to the **same value against `ShadcnColors.darkFallback`** (luminance
  > 0.8) — i.e. the toast is the light surface even in dark site mode, like
  main. Main's first-hand PIL of its 1440 capture = `#F8FAFC`; ours `#F7F8FA` is
  **Δ ≤ 2/channel**.
- **No border pixels:** test asserts every `GooeyShapePainter` in a live open
  toast has `borderColor == null` (fill-only). PIL of main: edge x+1 == x+3.
- **Silhouette bounding boxes** (from the ported geometry = main's formula, at
  main's docs config 350 / 18 / defaultShape → 24.3, seen open at bodyScaleY 1):

  | title | pill W | closed pill | opened body W |
  |---|---|---|---|
  | Success | 150.4 | 150.4 × 40 | 350 (full canvas) |
  | Error | 123.9 | 124 × 40 | 350 |
  | Action Required | 256.0 | 256 × 40 | 350 |
  | Processing (loading, pill only) | 190.0 | 190 × 40 | — |

  Closed pill height is exactly 40 (main's `_kToastHeight`); the opened body
  spans the full **350** canvas (main morphs the body to `size.width`). Pill W
  matches main's `_measurePillWidth`. Because the geometry is byte-for-byte
  main's path math (`seamOverlap = 4`, shoulder radius `roundness×0.62`, body
  seam at `pillHeight−4`), the dimensions equal main's for the same inputs
  (±0 px). Main's own capture: body **350 px**, pill **40 px** tall — exact.
- **Contrast on the light surface** (≥3:1, WCAG): success 3.10, error 4.55,
  warning 4.73, info 3.46, action 4.20, loading 4.55 — all clear 3:1 (pinned in
  `p6_f2_fix_test` / `p7f3_input_polish_test`).
