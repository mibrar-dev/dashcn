## Engine quirks found (documented in code + harness)

Widget-test isolates on this checkout have three fake-zone/clock traps,
each diagnosed by bisection and worked around in `frame_harness.dart`:

1. Bare-awaiting a deferred `loadLibrary()` future hangs forever (fake
   clock never advances for the loader). Loads must happen across pumps.
2. Only co-issued `loadLibrary()` calls resolve: a second *distinct* chunk
   issued after the first completed hangs. The isolate warm cache
   (`loadWarmPreview`) issues all six at once via `Future.wait`; later
   loads are cache hits. (Verified: card-alone passes, card-after-button
   hangs, button-reload passes, concurrent preload of all six passes.)
3. `toImage`, `toByteData` completion and async file writes only land on
   the real async zone; in the fake zone the first capture succeeds and
   every later binding op (even teardown) wedges with the tester idle.
   Captures run inside `tester.runAsync` (the SDK golden path) with
   `writeAsBytes(..., flush: true)`.

Consequence: fixed pump counts everywhere, no `pumpAndSettle` in new
tests, per-test 60–90 s timeouts, background runs with PID tracking.

## Fix note (orchestrator review, same day)

Rotation no longer applies to the desktop window and browser frames: they
are landscape-native, so `landscape` swapped them into tall portrait
windows. `DeviceSpec` gained `rotatable` (true for iPhone/Android, false
for desktop/browser); `sizeFor`/`paddingFor`/`totalFor` ignore orientation
for non-rotatable specs; `FrameBar` hides the rotate control for
desktop/web (kept for none/all/phones); the capture test shoots desktop in
portrait; new tests pin spec invariance and bar visibility. Screenshots
regenerated.
