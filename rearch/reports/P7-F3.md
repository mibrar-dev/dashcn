# P7-F3 — Input polish after P7-F2 (orchestrator visual QA follow-ups)

## Verdict on the four reported issues

1. **REGRESSION object_input "MM" wraps — confirmed, placeholder measured
   too narrow.** `segmentMinWidth` sized from digit advances only, but the
   empty segment shows the placeholder label (`MM`) painted in the
   non-mono muted placeholder style, whose `M` is wider than a mono digit.
   Fixed: the minimum is now `max(length` × max digit advance, measured
   placeholder width`) + caret allowance, and the overlay paints
   `softWrap: false, maxLines: 1, overflow: clip` (inherited by the
   caller's `Text` label). `EditableText` was already `maxLines: 1`.
2. **formatted_input gaps before separators — confirmed, reserve too big
   and centred.** The P7-F1 reserve (cursor 2 + slop 2 = 4px) centred left
   ~2px per side. Fixed: caret allowance only (2px, centred → ~1px/side),
   so segments butt against statics like one text field. Verified by a
   test measuring segment-box vs glyph edges (≤ 1.05px both sides).
3. **Triggers ~52px vs inputs h-9 — confirmed, two stacked causes in
   `object_form_field.dart`.** (a) The `minHeight: 36` box sat *inside*
   the `py-2` trigger padding (36 + 16 = 52). The minimum now sits
   outside the padding, like `EditableTextShell`. (b) At spacious density
   the trigger still rendered 38 vs input 36: the 16px leading icon drove
   the Row height (16 vs the 14px text line). Adornments are now capped in
   a zero-height `SizedBox` + `Center`, so the label drives the height and
   the icon paints through (CSS line-box behaviour; the row never clips).
   An `OverflowBox` was tried first and reverted: it asserts
   (infinite width) inside a `Row`. `FormattedInput` also changed from
   fixed `height: 36` to `minHeight: 36` so the whole family shares one
   height at roomy densities.
4. **gooey_toast status tint flips by mode — confirmed, chart tokens.**
   Success resolved to `chart1` (orange light / blue dark). Fixed: success
   = fixed green-600 `#16A34A`, warning = amber-600 `#D97706`, info =
   blue-500 `#3B82F6`, error = `destructive` (unchanged). Blue-600 was
   tried first and rejected: it fails 3:1 on the claude-dark surface, so
   the base moved one shade lighter (3.67 white / 3.9+ dark). `tone()`
   blends toward the foreground only when contrast on the toast surface
   drops below 3:1 (same-hue guard for overrides and exotic presets).
   Loading (`mutedForeground`) and action (`chart5`) keep their mappings.
   Computed ratios on fallbacks: green 3.30, amber 3.19, blue-500 3.67
   (light); all ≥ 3.4 dark. The 3-preset × light/dark loop asserts fixed
   equality + contrast for status tones.
