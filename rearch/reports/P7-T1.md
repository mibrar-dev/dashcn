### 1.3 tree: indent guides are hairlines, not blocks

`lib/registry/components/tree/tree_style.dart` — `TreeRow._guide` drew the
vertical line as

```dart
Positioned.fill(
  child: ConstrainedBox(
    constraints: const BoxConstraints.tightFor(width: 1),
    child: ColoredBox(color: color),
  ),
)
```

Root cause: `BoxConstraints.tightFor(width: 1)` only pins the *minimum* width
(`maxWidth` stays `double.infinity`), and a childless `ColoredBox` sizes to
`constraints.smallest`. `BoxConstraints.enforce` clamps that into the incoming
box, so the line's minimum width became the incoming tight width — the whole
`indentWidth` box. The guide therefore painted as a `16 × scaling` grey block at
the start of every child row (exactly the reported symptom).

The guide is now a stretched row:

```dart
Row(
  crossAxisAlignment: CrossAxisAlignment.stretch,
  children: <Widget>[
    SizedBox(width: lead),                                  // (indent - thickness) / 2
    SizedBox(width: thickness, child: ColoredBox(color: color)),
    Expanded(child: tick ? Align(...) : const SizedBox.shrink()),
  ],
)
```

`CrossAxisAlignment.stretch` hands each cell a tight height (the row height,
already bounded by the surrounding `IntrinsicHeight`), and `SizedBox(width:
thickness)` pins both width bounds, so the line is exactly `1 × scaling` wide
and spans the whole row, centred at `indent / 2` — under the parent row's
chevron, which `Center` puts in the middle of its own `indentWidth` box. The
tick still spans from the line to the end of the indent box, towards the row.

Two related fixes in the same method:

- **tick level off-by-one**: `index == depth.length - 2` was one level too
  shallow. `depth.length` is the row's level, and the guides run
  `i = 1 .. depth.length - 1`, so `depth.length - 2` never matches for a level-2
  child (the shallowest children never drew a tick) and for a level-3 child it
  drew the tick on the *grandparent's* chevron box instead of the parent's. The
  direct parent owns the last ancestor level, so it is `depth.length - 1`.
- **thickness** is `scaling` (1px at the default scale), the same "border
  token" scale the rest of the row uses for `indentWidth` / `itemGap` / the
  32px minimum row height.

Test added to `tree_qa_test.dart`: `indent guides paint a hairline under the
parent chevron`. It measures the guide's rendered boxes on the `report.pdf`
row (depth 2 → exactly one guide = line + tick) and asserts

- the line's painted width is `<= 1 × scaling`,
- the line's height is at least 4× its width (it spans the row),
- the tick's painted height is `<= 1 × scaling`,
- the line's centre x is within 0.5px of the parent row's chevron centre x.

Before the fix the same test measured a 16px-wide line and failed.

## 2. A test-harness trap worth knowing

`tree_qa_test.dart` now keys every pumped example
(`KeyedSubtree(key: ValueKey(preview.name))`). Several `treePreviews` entries
are the same `_FileTree` widget type, and Flutter reuses an element by runtime
type + key, so re-pumping `treePreviews[2]` over `treePreviews[1]` reuses the
first example's `State`: `_FileTreeState.didUpdateWidget` early-returns because
`widget.entries` is the same `const` list, so the second example silently
inherited the first's expand/selection flags. Without the key, both `every
preview pumps light + dark` and the new multi-select assertions were testing
the Default example repeatedly (my debug run of `treePreviews[2]` after
`[1]` rendered `archive` collapsed and no `2024.zip`). The docs app is not
affected (each example card owns its own element), but any test that pumps two
examples at the same tree position needs the key.

## 4. Key findings

1. **`BoxConstraints.tightFor` is not tight.** It only pins the minimum of each
   named axis (`maxWidth` stays `double.infinity`), so
   `ConstrainedBox(constraints: tightFor(width: 1))` does not make a child 1px
   wide. A childless `ColoredBox`/`ColoredBox`-like render object then fills
   its box (`computeSizeForNoChild` → `constraints.smallest`, and `enforce`
   clamps that minimum into the parent's box). The general recipe for a
   hairline in this framework is a stretched `Row`/`Column` with a
   `SizedBox(width: n)` cell — never `Positioned.fill` + `tightFor`.
2. **The tree tick was one level too shallow** (`depth.length - 2` vs
   `depth.length - 1`), so the `path` branch-line style never drew a tick on the
   shallowest children and drew it on the wrong box for deeper ones. Anyone
   reading `TreeBranchLine.path` should know that distinction was only fixed
   now.
3. **The chip preview was the only chip-family preview with a stateful
   example list**, so the stale `pressed 0/1` QA test could not be "moved" to
   another index — the closest equivalents are the removable counter and the
   selectable counter, and both are now pinned with real taps.
4. **`rearch/qa_gate.sh`'s `stray:` line is the scratch-file detector.** The
   untracked `$KIT/test/` tree was showing up there; removing it is what
   cleared that line (the many ` M docs/…` entries are other agents' mirror
   sync work and are pre-existing).
