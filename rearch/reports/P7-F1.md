# P7-F1 — FormattedInput typing is broken (user report 2026-10-11)

## Verdict on the suspected root causes

1. **Write-back caret reset — confirmed and fixed at the root.** `TextEditingController.text =`
   sets `selection: collapsed(-1)`, `composing: empty`. `_setValue` called
   `SegmentedTextController.setValues(notify: false)` after every keystroke,
   and `setValues` (unlike `setText`) had no equal-text skip, so it rewrote
   the focused box with identical text on every stroke: caret → invalid,
   IME composing cleared, next insertion misbehaved ("52" → "2" replacing
   "5"). Fixed in the primitive: per-segment skip when text matches +
   selection-preserving writes (valid selections clamped, invalid collapse
   at end, composing kept when still valid). `_setValue` itself is unchanged
   in shape; it is now safe because the primitive never touches a matching
   box.
2. **Fixed widths too narrow — confirmed by measurement and fixed.**
   With the resolved style (`text-sm` 14px + GeistMono) a test-font glyph
   advances 14.0px, so 3 digits need 42px + cursor; the previews used
   `width: 32` (3 digits), `36` (4 digits), `28` (2 digits), `40` (card-4).
   Earlier glyphs scrolled under the caret (looked like replacement).
   Fixed: `segmentMinWidth(style, length)` = `length` × max digit/`_`/`•`
   advance via `TextPainter` + cursor/slop reserve × density scale;
   `SegmentPart.width` / `SegmentRung.width` are now nullable overrides —
   null sizes from the style, a provided value only ever widens
   (`max(override, needed)`). Existing callers passing widths still compile.
3. **OTP-like behaviour — implemented.** Typing appends; a full box advances
   with caret at next start (IME-composing defers); Backspace in an empty
   box steps back and deletes the previous box's last glyph (non-empty at
   0, or arrows at edges, cross without deleting, caret at end/start
   respectively); paste/over-type distributes across following boxes through
   each box's `inputFormatters` (digits-only previews strip separators);
   controlled / controller / uncontrolled share one `_handleChanged` path.
   The per-box `LengthLimitingTextInputFormatter` was removed on purpose —
   it truncated paste overflow before `onChanged` could distribute it.
   Lengths are still enforced (primitive clamp + head/overflow split).

## What changed

- `primitives/text_editing/segmented_value.dart`: `SegmentPart.width`
  `double` → `double?` (null = auto). Docs updated. `hasShape`/`withValue`
  unchanged in logic (null-aware `==`).
- `primitives/text_editing/segmented_editing.dart`: `setText`/`setValues`
  skip equal text, preserve/clamp selection + composing via `_write`;
  new `maxSegmentGlyphAdvance` + `segmentMinWidth` helpers.
- `components/formatted_input/formatted_input.dart`: `_handleChanged` with
  `_handleOverflow` (distribute + land on first incomplete, caret at end),
  `_filterForSegment`, `_advanceTo` (caret at 0), rewritten `_handleKey`
  (backspace-delete-back, edge arrows with caret placement),
  `_effectiveWidth` floor, `_segment` uses `part.inputFormatters` (no
  limiter), `onSubmitted` advances with caret at start.

  Old 32/36px boxes clipped by 10–20px.
