API (all per brief): `enum ButtonStatus { idle, loading, success, failure }`;
`status:` (controlled, parent-owned, no internal transitions);
`onPressedAsync: Future<void> Function()?` (uncontrolled: press → loading
synchronously → success on return / failure on throw, error to `onAsyncError`,
never rethrown); `successLabel`/`failureLabel` (null keeps `child`);
`statusResetDuration` (default `buttonDefaultStatusReset` = 1.5s, null stays);
`onStatusChanged` (every status entered, both legs — controlled leg reports
post-frame so a parent rebuild never nests a setState).
Loading disables the button regardless of `enabled`. Sync buttons
(`onPressed` only) render byte-identical output to before — the status slot
exists only when `status != null || onPressedAsync != null`.

### Design decisions (brief deviations, all deliberate)

1. **Width stability via reserved slot.** Statusful buttons always lay out a
   leading slot (`max(spinnerSize, statusIconSize)`, default 16 + `spacing.sm`
   gap) whose idle child never unmounts; the status icon overlays it.
   Icon buttons (`size.icon`, no adornments) swap the child inside the fixed
   36 box. Group items share the core automatically. `Toggle` untouched (N/A
   per brief); the `async` (FutureOr-builder) component is a different
   concept — noted, not changed.
2. **Enter animates, exit drops instantly** (`AnimatedSwitcher` 175ms enter,
   `reverseDuration: Duration.zero`). A fading-out spinner lingered in the
   tree while the next state was live and broke existing spinner-count
   assertions (`blocks_forms*` `finishSubmit` expects exactly one `Spinner`;
   two consecutive submits showed stale + entering = 2). Labels still
   cross-fade both ways (all labels stay mounted by design). Documented in
   README + code comment.
3. **`ButtonStatusStyle` lives in `button_style.dart`, slices re-exported.**
   `check_user_theme` only allows `button_style.dart` imports in user themes,
   so the Studio-editable status slice must be reachable through it; the
   re-export keeps one import for overrides. Verified: `check_user_theme
   --strict` = 0.
4. **New dep `button → spinner` (+ `foundation/icons`).** The loading visual
   reuses the `Spinner` component (no duplicated painter); declared in
   `meta.json` `deps`. Same-layer/same-rules as the existing
   `empty_state → button` precedent. `layers`: 0 errors.
5. **Semantics boundary.** The announcement node uses `container: true` —
   without it the label merged with the button text at an ancestor
   (`Loading\nGo`, found by probe) and `bySemanticsLabel('Loading')` missed.
   Now exact `Loading`/`Success`/`Failure` labels with `liveRegion: true`.
6. **Reduced motion:** transitions go zero + loading shows the static
   `loadingIcon` glyph (default `loaderCircle`) instead of a ticking spinner.
7. **Failure tint scope:** status *icon* only (destructive token for
   non-destructive variants, foreground for `destructive`) — not the whole
   surface, so the variant × state token matrix is untouched.

### Blocks (submit wiring only, per coordination note)

- login-01/02/03, signup-01, account-01 profile/password, pricing promo:
  `_submit()` now returns `Future<bool>` (validation + focus-first-invalid
  preserved); the button maps false → failure via a throwing closure
  (`return` = success / `throw` = failure contract, documented in README).
  Manual `_submitting` flags + hand-built spinner children deleted; spinner
  imports + `"spinner"` meta deps removed (9 block metas).
- login-02/signup-02 split forms: `submitting` param removed, `onSubmit`
  became `Future<bool> Function()`; keyboard `onSubmitted` paths use the
  non-throwing core (no unhandled errors).
- account-02 (no validators): `_save` directly as `onPressedAsync`.
- otp-01: controlled leg with a block-owned public `ButtonStatusController`
  (`status:` + `onPressed`) so the button press AND the `InputOtp`
  auto-submit (`onCompleted`/`onSubmitted`) drive one machine (reset timing
  reused from the tested controller).
- P7-B1 tests untouched and green, except one 1-line helper fix in
  `blocks_interactive_test.dart`: `_buttonEnabled` now mirrors the widget
  (`... || button.onPressedAsync != null`); without it every rewired submit
  button reads as disabled.

## Key findings

- `AnimatedSwitcher` exit fades leave stale widgets across duration-less
  test pumps; `reverseDuration: Duration.zero` keeps entries animated with
  no lingering tree/semantics.
- Semantics labels merge upward through `Clickable`'s gesture/focus nodes;
  a `container: true` boundary keeps live-region labels exact.
- `tester.pump(duration)` vs `pump()` changes post-completion frame timing
  under zero-duration transitions (UNVERIFIED mechanism — observed
  1-frame lag in one reduced-motion sequence; worked around by matching
  the no-duration-pump sequence; non-reduced flows consistently need one
  pump).
- Opacity-0 entering widgets are hidden from the semantics tree until the
  fade completes — semantics assertions must pump past the transition.
