# P7-G2 — port the working gooey toast from `main`

## What was wrong

The queue-based rewrite anchored toasts inside the caller's local box (the
preview stage), so a toast covered its own trigger, and it dropped the
reference's timing: the body grew from a `pillHeight * pillScaleY` that had
already been compressed, so the silhouette rendered at roughly half the pill
height while the text stayed full size — the "broken" toast.

## What was ported

`main`'s behaviour, shapes, timing and presets, adapted to the new architecture:

- **Root-overlay anchoring.** `GooeyToastController.showGooeyToast` inserts
  `OverlayEntry`s into the root overlay (like `main`), so toasts anchor to the
  window edge. This is why the controller no longer goes through
  `primitives/toast_queue`.
- **Full lifecycle.** Thin pill → body expands after the 150 ms expand delay →
  holds for the 4 s collapse delay → collapses → leaves at 6 s. Hover/press/focus
  pauses the countdown.
- **All shapes.** The metaball silhouette is ONE closed contour (concave cubic
  fillets from the pill into the body), so a stroked border never doubles up at
  the seam. `defaultShape`/`soft`/`sharp`/`capsule`.
- **All presets.** Six animation presets (sileo/smooth/snappy/bouncy/fluid/
  springEasing, with the piecewise Sileo spring stops) and four body-animation
  presets (fade/fadeSlide/fadeScale/none).
- **All variants.** success / error / warning / info / action (with an inline
  action chip) / loading (pill only, never expands) + the promise morph
  (loading → "Upload Complete" with body) through the staged
  collapse → compact → expand transition.
- **Six positions** (left/center/right × top/bottom) with RTL mirroring.
- **Interactive demos.** Interactive Reply (inline composer that transitions to
  "Message Sent") and Booking Multi-State (loading → confirmed → gate update),
  both in one toast slot.
- **Architecture rules honoured.** Flat component folder, reusable machinery in
  `primitives/gooey/`, every file ≤ 400 lines, widgets-only, no
  Material/Cupertino, theme via `ThemedColor`, density spacing, reduced motion,
  RTL.

## Tone decision (deviation from the literal `main` palette)

`main`'s status tones (`#63C65E` green, `#EF5E5E` red, `#EABB4B` amber,
`#6EA8FF` blue, `#7A8DFF` indigo, `#8A8F98` grey) are tuned for a **dark** toast
surface; on the kit's light `popover` they fall below 3:1, which the standing
P7-F3 contrast contract forbids. The tones are kept as fixed, user-overridable
theme defaults in the same hue family, picked to clear 3:1 against **both** the
light and the dark `popover`:

| state | tone |
|---|---|
| success | `#16A34A` green |
| error | `destructive` token (unchanged from P7-F3) |
| warning | `#D97706` amber |
| info | `#3B82F6` blue |
| action | `#6366F1` indigo |
| loading | `#6B7280` grey |

`ensureToneContrast` still lifts any tone too weak for a customised surface.

## API changes (clean break, documented in README + meta.json)

- `GooeyToastController.showGooeyToast` now takes the **build context first**
  (it resolves the root overlay from it): `controller.showGooeyToast(context, options)`.
  The top-level `showGooeyToast(context, options)` keeps its signature.
- Stacking settings from the queue (`spacing`, `overlapStackOffset`,
  `pauseAutoDismissWhenMultiple`, `maxVisibleCount`,
  `dismissWholeStackWhenMultiple`) are gone; the stack uses the fixed
  `kGooeyStackGap` (8) and `kGooeyEdgeInset` (16) of the reference.
- `GooeyToastPosition` keeps three values (`left`/`center`/`right`); the
  unreachable `centerLeft`/`centerRight` are covered by `expandDirection`.
- New public types: `GooeyToastPayload`, `GooeyToastRecord`, `GooeyToastScope`,
  `GooeyToastCard`, `gooeyToastThemeOf`, `GooeyToastDetails`.
