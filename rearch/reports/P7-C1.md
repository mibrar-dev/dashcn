## 1. What changed

### 1.1 Registry (root-cause) fixes

| File | Fix |
|---|---|
| `components/carousel/carousel.dart` | `Stack(clipBehavior: Clip.none)` → `ClipRect(child: Stack(clipBehavior: Clip.hardEdge))`. The old stack let neighbour pages draw outside the viewport, so a `viewportFraction: 1/3` carousel spilled past the card edges. |
| `components/chip/chip.dart` | Added `Chip.onDeleted` (`VoidCallback?`) plus a private `_ChipDeleteIntent` wired to Backspace/Delete through `Clickable` shortcuts/actions. A chip without `onPressed` is still a static token (`interactive = onPressed != null \|\| onDeleted != null`), so a static chip does **not** become focusable — only a deletable one does. |
| `components/breadcrumb/breadcrumb.dart` | Added `BreadcrumbLink` (`onPressed`, `focusNode`, `autofocus`): a `Clickable` crumb that is `mutedForeground` at rest and `foreground` + `TextDecoration.underline` on hover/press/focus, with a click cursor. The current page stays a plain `Text` (drawn in the body foreground), so the trail is interactive without losing the shadcn "current page is not a link" rule. Needs `import '../../primitives/clickable.dart'` + `theme/color_tokens.dart`. |
| `components/pinned_sheet/pinned_sheet.dart` | `SheetController._attach` no longer calls `notifyListeners()` synchronously from `PinnedSheet.initState`. With a `ListenableBuilder` (or `onIndexChanged`) listener mounted alongside the sheet this threw *"setState() or markNeedsBuild() called during build"*. The notification is now deferred to a post-frame callback, guarded with `identical(_state, state)`. Regression covered by the preview itself. |
| `components/tree/tree_style.dart` | `TreeRow` now wraps its `Row` in a `ConstrainedBox(minHeight: 32 * scaling)` inside `IntrinsicHeight`, so a row has the shadcn tree-row height instead of collapsing to the icon height (the "tiny, misaligned rows" complaint). Guides stay bounded by `IntrinsicHeight`; `TextScale`-driven rows still grow past the minimum. |

`components/breadcrumb/meta.json` updated for the new runtime dep
(`primitives.clickable`) and the `BreadcrumbLink` API entry — generated manifest
`lib/registry/manifests/registry.json` regenerated after.

No theme files (`*_theme.dart`, `chip_style.dart`, `tree_style.dart` rows other
than the row height, `carousel_style.dart`, `breadcrumb_style.dart`) were touched,
so user-owned overrides and the theme schema are unchanged.

## 4. Key findings

1. **`SheetController._attach` notifying during `initState` is a real registry
   bug.** Any listener mounted with the sheet (a `ListenableBuilder` on the
   controller, `DotIndicator`, `setState`) crashed with "setState() called
   during build". Deferring the notification is the smallest safe fix; the
   existing `pinned_sheet_test.dart` passes unchanged, and the preview's
   `% open` readout works.
2. **The blank pinned-sheet preview had two separate causes**: (a) it rendered
   the sheet at its closed stage so only a mostly-empty stage showed, and (b)
   the sheet had no `DrawerContainer` chrome, so even the visible part was raw
   content. Both are fixed; each example now opens from the trigger and has
   `DrawerContainer` chrome.
3. **`onDeleted` keeps the static/pressable split intact.** `interactive` is
   now `onPressed != null || onDeleted != null`; a chip with only `onDeleted`
   is focusable (needed for Backspace/Delete) but is not a button and does not
   swallow taps — the regression pinned by `chip_test.dart` ("a read-only chip
   builds no tap target") still holds.
4. **`overlay_entry_capture_leak`-style test harness trap (mine, worth knowing):
   `Overlay` keeps the `initialEntries` it captured in its *first* build across
   later `pumpWidget` calls.** My `_pump` helper originally captured the stage
   size in the entry's builder closure, so re-pumping at 375 and then 720
   rendered 375 twice and the responsive test failed. The entry now reads
   late-binding module fields (`_shownBuilder` / `_shownSize`).
5. **A carousel ticker needs small steps, not one big pump.** A single
   `tester.pump(Duration(seconds: 3))` is one tick; the carousel's hold timer
   restarts on that tick so no page advances. Autoplay tests must pump in
   ~300ms frames (as the existing `carousel_test.dart` autoplay group does).
6. **A sheet body's inline Close button can sit below the clip at a snap
   stage.** At the 40% stage in a 240px stage the body's Close was clipped, so
   the demo was only closable from the trigger row. The trigger row now owns
   Close/Half/Open and the body's button is "Done".
7. **Tree icons must not be `leaf`-driven.** `leaf` is false for an empty
   folder (`Pictures`), which is exactly why it drew a file glyph. The preview
   now maps from the entry's own `folder` flag; folders use `folderOpen` when
   expanded and `folder` when closed.
8. **Preview example lists grew (chip 3→4, carousel 3→5, pinned_sheet 2→5, tree
   4→4, breadcrumb 3→4)** — `previews_test.dart`, the manifest and the docs
   codegen were all regenerated so the docs `Select` and the deferred preview
   registry match.

## 5. Open questions

- **`flutter build web --release` and the `p7c1-*.png` captures need the
  orchestrator to land P7-F3's button/gooey fixes** (or to re-run them once
  those agents finish). Everything my brief touches is green; the build errors
  are in files I am forbidden to edit.
- `_FileTree` rebuilds from `widget.entries` on change and re-applies
  expand/selection flags **by node name**, which is why "Large" lazy-loads
  correctly. If a file tree ever holds duplicate names at the same level the
  flag mapping would be ambiguous — fine for a preview, worth noting if the
  preview grows.
- The breadcrumb `Responsive` example collapses at 420px, chosen so the
  375px phone stage trips it and 720px does not (the docs stage is 720). If a
  component page is ever given a narrower desktop stage this threshold would
  need to read `MediaQuery` instead of `LayoutBuilder`.
