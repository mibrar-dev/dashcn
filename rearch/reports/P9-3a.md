## Fix round 2 (orchestrator screenshot review)

1. **Errors on first render (REAL UX bug, fixed with a documented
   deviation).** Every flow `FormItem` now sets `showErrors:
   {FormValidationMode.submitted}` — errors surface on submit only.
   The brief prescribed `{changed, submitted}`, but that set does NOT hide
   mount-time failures, proven three ways: a bare `FormScope` +
   `FormItem` + `Input` probe, every flow screen, and the kit's own
   `Login01` block (same set, shows 2 errors on first render). Root
   cause: `FormEntry.didChangeDependencies` attaches with mode `initial`,
   then the field's `FormValueSupplier.didChangeDependencies` reports the
   initial value once the handle exists — the second attach lands as mode
   `changed`, so any set containing `changed` flags pristine fields.
   Fixing the mount report itself belongs in `primitives/form_core`
   (outside this brief's scope), so flows use submit-only surfacing.
   Tradeoff, stated in code comments: no live-while-typing errors; after
   a failed submit the message updates on the next submit (standard
   validate-on-submit UX). New tests per form flow assert pristine render
   shows nothing and empty submit reveals the errors (auth sign-in, sign
   up, forgot + OTP-never-errors; checkout address + payment).
2. **Screenshot harness wrapped in the app text style.** Captures now
   apply exactly what `DashcnApp` provides above the theme
   (`DefaultTextStyle` with `typography.sans` + foreground,
   `IconTheme` with foreground) instead of a bare `Theme`, so light-mode
   text renders. All 34 screenshots regenerated (unopened — orchestrator
   to review).

## Fix round 1 (orchestrator review: swipe hit-test bug)

The "scrollable tap-arena pathology" from the first report was a genuine
hit-test bug in `swipe_actions.dart`, not a `flutter_test` artefact. The
content's close-on-tap `GestureDetector` (translucent) wrapped
`Transform.translate`: the transform moves painting and child hit-testing,
but the detector's own hit box stayed the full un-translated row, covering
the revealed actions. A tap on an exposed action then entered the arena
with the close-tap on top — the row closed and the action never fired (in a
real app: tapping "Delete" just closed the row).

Fix: the close-tap detector moved INSIDE `Transform.translate`, so its hit
area travels with the content and never overlaps revealed actions. The
outer horizontal-drag detector is unchanged. Restored real assertions:
checkout cart delete and chat thread Mute/Delete assert the callback fires
after `tester.tap` on the exposed action; new regression test (ListView of
3 rows, open row 2, tap its action) asserts the callback fires exactly once
and the row stays open (`controller.isOpen`). The `settleSwipeOpen`
transform poll stays as the deterministic wait for full reveal (a tap on a
still-settling row would otherwise land on the covering content).
`SwipeActionsController` stays as a real feature (programmatic open/close,
unit-tested). All gates below were re-run after the fix.

## Key findings (read before QA)

1. **Brief said `swiper` + `dot_indicator` for onboarding pages; `swiper`
   is a swipe-to-open *drawer* wrapper** (`swiper.dart`: "reveals a drawer
   or sheet panel"), not a pager. Onboarding pages use `carousel`
   (`viewportFraction` 1, `onIndexChanged`) + `dot_indicator` instead.
   No code duplicated; flagging the spec mismatch.
2. **Swipe reveal + tap routing under scrollables.** Settled facts: (a)
   settle animations need the starting frame *plus* the duration frame —
   a single `pump(300)` leaves the final build unrendered
   (`settleSwipeOpen` polls the row's translate transform instead);
   (b) `tester.drag` delivers moves with no inter-event frames and the
   arena swallows the slop-sized first move (~20 px), so `dragOpen` aims
   `(0.9 × total + 20)` — inside the open band, clear of the 1.05 dismiss
   line; (c) the earlier "tap never fires" reports were the hit-test bug
   above (fixed), not harness pathology — `debugPrint` throttling additionally
   made diagnosis logs unreliable (identical lines repeat, lines drop), so
   future gesture debugging should use arena diagnostics or state polls,
   not prints.
3. **Auth link rows overflow at 390 px** (`Row` + link `Button` = 350 px in
   310 px): fixed with `Flexible` on the label in sign-in/sign-up/OTP.
4. `rearch/screenshots/pilot/*.png` show as modified — rewritten by the
   qa_gate full-suite run (`pilot_screenshots_test`), not my changes.
5. Flows validate clean at 1280 by construction (centered `maxWidth`
   400/480 columns); only the 390 stage is asserted in tests.
6. **Round 3**: `swipe_actions` is now `listed: true` with a real
   `preview.dart`, so it rides all listed-component machinery (previews
   test, scorecards, docs registry). Its preview needed explicit token
   colours + an opaque surface to pass scorecard contrast under a bare
   `Theme` — a useful pattern for future previews.
