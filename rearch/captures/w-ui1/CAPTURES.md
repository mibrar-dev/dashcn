# Captures — Batch 1A density + sizing foundation (w-ui1, port 8861)

Docs sizing section: `/docs/theming` → “Sizing and density”.
Docs built from this branch (`docs/build/web`), served at
`http://127.0.0.1:8861` via `python3 -m http.server`.
Browser shots use real fonts; `test-*` shots come from `flutter test`
(Ahem test font — layout proof only).

## Browser shots (real fonts, docs web build)

- `sizing-1280x800-light.png` — 1280×800, light. Sizing section header,
  intro copy and the `sizing` code sample (tokens, phone auto-touch,
  per-instance overrides). Demos continue below the fold.
- `sizing-1280x800-dark.png` — same framing, dark mode (via
  `localStorage docs.theme.brightness=dark` + reload; the app does not
  follow `prefers-color-scheme`).
- `sizing-1280-demos-light.png` — 1280×800 crop from a 1280×2500 shot:
  all three live rows — Compact (control 32, icon 16), Comfortable
  (control 40, icon 20), Touch (control 48, icon 24) — each with a
  Button + icon Button + ListTile. Buttons grow left→right; tiles stay
  single-line truncated. Light.
- `sizing-1280-demos-dark.png` — same rows, dark. Touch row is visibly
  tallest; tile subtitles stay one step smaller.
- `sizing-375x812-light.png` — 375×812 crop: sizing header + intro +
  code start on a phone viewport, light. No horizontal overflow.
- `sizing-375x812-dark.png` — same framing, dark. No overflow.

## Flutter-test layout proofs (Ahem font, exact viewport sizes)

Generated by the (temporary, since removed) `zz_sizing_capture_test`
via `ensureVisible(DensityDemos)` + `RepaintBoundary.toImage`:

- `test-sizing-1280x800-light.png` / `test-sizing-1280x800-dark.png` —
  full sizing section (code + all three demo rows) at exactly 1280×800.
- `test-sizing-375x812-light.png` / `test-sizing-375x812-dark.png` —
  same at exactly 375×812. Phone widths render the touch row; no
  `RenderFlex` overflow in any density (the test asserts
  `takeException() == null`).

## What looks wrong

- Nothing overflows. On the 1280 demos crops the touch “Save changes”
  button is widest (correct: touch padding 24 vs compact 16).
- List-tile titles truncate with ellipsis at every density (by design:
  “truncate, never grow the row”); the truncation point moves left as
  density grows, which is expected.
- No interaction video: the sizing demos are static rows (no controls
  to operate). The section’s live behaviour — touch auto-switch on
  phone widths — is covered by the 375 captures + the
  `density_tokens_test` phone-width test, not by a video.
- Browser scrolling is not scriptable against the Flutter canvas in
  this setup, so the 1-viewport shots are crops from taller viewports
  (same pixels, viewport-sized crops) plus the scrolled flutter-test
  captures. Framing is honest; nothing was reflowed for the shots.
