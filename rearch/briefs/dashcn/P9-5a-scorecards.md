# P9-5a — Trust scorecards: generator

Prerequisite: P8-2 accepted. Spec: `DASHCN_FEATURES_PLAN.md` §P9-5 (binding). Read the existing tests layout under
`$APP/test/registry/**`, the manifest, and how docs previews are built (`$DOCS/lib/previews/**`, read-only).

## Rules
Never invent numbers. A metric that wasn't measured is `null` and renders as "not measured". Frame time is labelled
test-environment/relative.

## Tasks
1. Harness `$APP/test/scorecards/scorecard_harness_test.dart` (generated by the tool, checked in). For each
   user-facing component it pumps the component's canonical example (find or add a minimal `scorecardExample` per
   component in `$APP/test/scorecards/examples/<id>.dart`, built with the kit only) and records:
   - a11y: `textContrastGuideline`, `labeledTapTargetGuideline`, `androidTapTargetGuideline`,
     `iOSTapTargetGuideline` (pass/fail + message), and semantics present (has a label or role);
   - rtl: pumped under `Directionality(rtl)` with no exceptions/overflow and leading-edge mirrored (assert the first
     child's x-position flips);
   - frames: 120 frames of the example's interaction (hover/press/open where applicable) with
     `Stopwatch` around each pump, reporting p50/p90 ms;
   - output: one JSON line per component, via `printOnFailure`-free stdout markers (`SCORECARD {...}`).
2. `$APP/tool/gen_scorecards.dart`: runs `flutter test test/scorecards --reporter json`, collects the markers, counts
   tests per component (test names/paths under `test/registry/components/<id>/` plus `tags: component:<id>`), and
   writes `$APP/lib/src/manifests/scorecards.json`
   (`{generatedAt, commit, flutter, components: {<id>: {a11y, rtl, frames, tests}}}`). `--check` compares everything
   except `generatedAt`/`commit`/frames numbers and exits 1 when stale.
3. Tests for the tool's parsing and aggregation: `$APP/test/scorecards/gen_scorecards_test.dart`.

## Owns
`$APP/test/scorecards/**`, `$APP/tool/gen_scorecards.dart`, `$APP/lib/src/manifests/scorecards.json`.

## Gates
`rearch/qa_gate.sh`, `dart run tool/gen_scorecards.dart --check`, `check_names`. In the report, list every component
that fails an a11y/RTL check, with the guideline message. These are findings for the orchestrator. Do not fix
components in this batch.

## Report
`$KIT/rearch/reports/P9-5a.md`

## Notes (orchestrator, before launch)
- Final paths: `$APP` = `$KIT/dashcn`, `lib/src/`, theme `Theme`/`ThemeData`. New source files must pass
  `check_names` (no "shadcn").
- The harness pumps ~85 components: NEVER `pumpAndSettle()` on anything that may animate forever (spinner,
  skeleton/shimmer, marquee, carousel autoplay, progress indeterminate, typing indicator, number ticker). Use
  `pump()` + `pump(Duration(milliseconds: 500))`, a per-test `Timeout(Duration(seconds: 60))`, and measure one
  component first before running all (lesson from P9-1).
- The frame-time metric runs in the test environment: label it exactly "test environment (relative)" and never present
  it as device performance.
- Run long test runs in the background with their PID, poll ≤ 60 s, kill by PID if they overrun. Keep outputs short.
